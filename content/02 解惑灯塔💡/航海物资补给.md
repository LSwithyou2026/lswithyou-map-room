> [!note]- 2026.8.3 制作个人网站时我走过的弯路（可借鉴）
> （以下都是本人亲身走过的弯路，直接导致了我烧了周额度的70%左右，制作周期拉长，返工次数大大增加，供你参考和借鉴）
> - 没先冻结网站定位和信息结构，导致边做边增加、删除、移动板块。
> - 一开始把网站做得太像求职简历，后来才明确它还用于交朋友、建立连接和展示个人。
> - 先做了电脑端，再强行改手机端，造成图片裁切、文字残缺、页面过长。
> - 手机预览最初只是缩小桌面页面，不是真正的响应式手机布局。
> - 首版排版过于规整和死板，后来反复调整信息密度与自由度。
> - 板块序号经过多次增删移动，导致编号反复重排。
> - 文案没有一次确认，经常在实现后继续逐句改字、换行和主次。
> - 动效和渐变加得太早，出现文字被遮挡、黑底黑字、金字重影等问题。
> - 为解决白底金字不清楚而统一加黑底框，但规则过于粗暴，引发多轮颜色冲突。
> - 图片先直接使用原图，首页照片一度约 9.3MB，导致打开和滚动加载缓慢。
> - 活动照片最初纵向排列，占用大量页面长度，后来才改为横向滑动。
> - 兴趣板块最初需要不断上下翻找选项，后来才改成侧栏切换。
> - 教育信息先写得太详细，之后才因隐私需求删掉具体院校名称。
> - 发布路线反复尝试本地地址、Sites 和 GitHub；本地链接无法分享，部分托管链接又遇到ICP备案提示。
> - GitHub 发布初期依赖网页手动上传，遇到上传未完成、文件漏传和重复提交。
> - 修改后有时只更新了页面文件，没有同步更新样式、脚本或图片，需要再次补发。
> - 多次零散反馈造成局部修补相互影响，本可以先集中列出完整修改清单。

> [!note]- 2026.8.3 网站在本地完成后到输出公开链接的每一步
> 写在开头的话：以下流程大概了解即可！你只要用自然语言告诉AI：“我想要一个别人点一下就能打开的链接，同时也方便我未来修改，你帮我部署，最后返给我一个链接即可。”不需要去告诉AI每一步怎么做，当然你也可以把下面这段话直接复制给AI。（因为AI也可能给你部署一个 `chatgpt.site` 版本，但在微信或中国大陆访问时，很容易出现过“未完成ICP备案”的安全提示。所以你也可以告诉AI走Github Pages这一套的链路）
> 1.本地检查  
> 先通过 `localhost:3000/mobile` 预览和修改，但这个地址只能在你的电脑上访问，不能直接分享。（修改的步骤尽量控制在这一步，省token）
> 2.生成正式网页文件  
> 把开发中的代码打包成浏览器可以直接访问的 HTML、CSS、JavaScript 和图片文件。 
> 3.优化手机端  
> 重新适配手机屏幕，解决文字裁切、图片变形、页面过长、按钮难点等问题。
> （方便的话可以多用几个手机打开看看，每个手机尺寸不一样，呈现出的画面也会有细微差别。）
> 4.优化加载速度  
> 压缩全部图片；首页图片优先加载；其他图片在后台预加载，保证滑到时尽快出现。 
> 5.上传到 GitHub  
> 创建并使用了名为 `LSwithyou2026.github.io` 的 GitHub 仓库，把网页文件、样式、脚本和图片上传进去。  （链接名称可以自己取）
> 6.开启 GitHub Pages  
> 让 GitHub 把仓库里的网页文件自动发布为公开网站。
> 7.等待自动部署  
> 每次修改上传后，GitHub Actions 会重新构建和发布。我们等待它显示成功后再检查网站。

> 最终链接是：https://lswithyou2026.github.io/
